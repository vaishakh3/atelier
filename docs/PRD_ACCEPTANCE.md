# PRD acceptance and remaining release gates

This matrix traces `AI_BIM_MVP_PRD.docx` to the current standalone desktop implementation. “Implemented” means code exists for the stated bounded workflow, with the listed automated evidence. It does not mean professional acceptance, certification, or completion of the PRD's design-partner pilot. Final packaged GUI results belong in [VALIDATION.md](VALIDATION.md).

The authoring scope remains low-rise architectural BIM: rectangular walls/hosted openings, simple polygon slabs/rooms/flat roofs and concept extrusions, and regular straight stairs. Residential generation supports one or two storeys; authored models can contain more levels. Structural analysis, detailed MEP design, general freeform solid modeling, fabrication-grade documents, automatic permits and regulatory sign-off remain outside the supported scope.

## Residential services extension — 0.6.0

This user-authorized extension adds concept electrical/plumbing coordination to the existing architectural workflow. It is separate from statutory engineering sign-off.

| Scope | Implemented and verified | Boundary |
|---|---|---|
| Services-aware layout review | Wet-area grouping/stacking distance proxies and proposed wall/slab/stair penetration review with source IDs. | No optimality, physical clearance, approved shaft or structural opening claim. |
| Electrical/plumbing plans | Editable room-hosted points, conceptual circuit groups, cold-water/drainage branches, multi-floor routing, explicit acceptance, save and undo/redo. | Rectangular classified rooms, up to 100 programme rooms, one panel/inlet/outlet; hot water, venting, specialist/pool design and fabrication are excluded. |
| Cost/construction time | Current route lengths and fixture counts, entered rates/output per crew-day, visible unknowns, services added to overall estimate and reviewed installation phases. | Drawn route centrelines are not conductor procurement quantities; shared branches may overlap. Manual legacy tasks are retained for reconciliation. |
| Limited calculations | Single-phase demand-current identity and horizontal-run/gradient fall arithmetic, with reference cases and visible assumptions. | No cable, protection, fault, earthing, hydraulic sizing, installation safety or legal certification. |
| Connected demonstration | Browser and installed macOS house → services → changed bathroom function → six rerouted connections → reviewed estimate/schedule → accept/undo/redo. | Example prices are illustrative. Room-function swap retains shells/doors/windows and requires architectural access/ventilation review. Full engineering and competitor superiority are not established. |

## Familiar model workflow — 0.6.1

Quick access (Q / Cmd/Ctrl+K), command and model search, camera presets, fit-all/selection, visible-element selection, temporary hide/isolate/show-all, drawing-tool repetition and guarded keyboard shortcuts are implemented. The existing central canvas, project browser, contextual inspector and coordinated plan/section/elevation workflow remain. [VALIDATION.md](VALIDATION.md) distinguishes browser/automated controls evidence from the installed smoke/relaunch checks and future-update Keychain limitation. This historical controls milestone does not establish all Forma capabilities, zero learning effort or a measured switching advantage. The 0.7.0 source extension below adds bounded saved-view, proposal and imported-context workflows; native proprietary-format editing and equivalent environmental simulation remain outside scope.

## External release and pilot gates

1. **Three to five design-partner firms** complete the PRD journey on representative low-rise work: create/import → review/accept/revert an AI edit → document → estimate → schedule → compare/export.
2. Independent reviewers agree measurement tolerances, validate cost/schedule inputs and check every reported trade-off against the supported scope. Numeric tolerances are not yet established; do not invent them.
3. Measure the proposed AI correctness, review/correction time and repeat-use goals. The PRD proposes at least two firms reusing the product; this is an outcome to observe, not a completed code check.
4. Extend the recorded macOS integration evidence to the complete agreed acceptance journey, recovery drills and each target OS. Supply publisher signing/notarization/feed credentials before claiming public signed distribution or automatic updates.
5. Independently review the approved sequencing alternatives and close or explicitly accept interoperability, accessibility and operational limitations. None of these records imply structural approval, code-compliance sign-off or a general-purpose CAD system.
